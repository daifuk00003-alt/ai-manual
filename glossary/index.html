    用語集¶

    AIツールを使っていると出てくる基本的な用語を、カテゴリ別にまとめています。専門用語には、できるだけ平易な言葉と具体例を添えています。

    各項目は「一言でいうと」→「もう少し詳しい解説」→「具体例」の順で構成しています。まずは太字の一言だけ読めば意味がつかめるようにしています。

    1. AI・LLMの基本用語¶

    LLM（大規模言語モデル、Large Language Model）¶

    一言でいうと: 大量の文章データを学習し、人間のような自然な文章を生成できるAIモデル。

    インターネット上の膨大なテキストを学習することで、単語と単語のつながり方の「パターン」を覚え、次に来る単語を予測する形で文章を生成する。ChatGPTやClaude、GeminiなどのチャットAIは、いずれもLLMを土台にして作られている。

    具体例: 「今日の天気は」と入力すると、学習したパターンをもとに続きの文章を予測して生成する。

    トークン（Token）¶

    一言でいうと: LLMが文章を処理する際の最小の単位。

    人間は文章を「単語」や「文字」で捉えるが、LLMは文章を「トークン」という単位に分割して処理する。日本語の場合、1トークンは1〜2文字程度になることが多い（英語なら単語の一部やまるごと1単語）。トークン数は料金や、一度に読み書きできる文章量の上限（コンテキストウィンドウ）に直結する。

    具体例: 「こんにちは」は約3〜5トークン程度に分割される。

    プロンプト（Prompt）¶

    一言でいうと: AIに対して与える指示や質問の文章。

    プロンプトの書き方次第で、AIの返答の質は大きく変わる。目的・条件・出力形式などを具体的に書くほど、意図に近い応答が得られやすい。この「良いプロンプトを設計する技術」をプロンプトエンジニアリングと呼ぶ。

    具体例: 「この文章を100字で要約して」という指示文もプロンプトの一種。

    コンテキストウィンドウ（Context Window）¶

    一言でいうと: AIが一度に読み書きできる文章量の上限。

    会話やアップロードした資料は、すべて「トークン」としてこのコンテキストウィンドウに収まる範囲でAIに渡される。上限を超えると、古い会話の内容などが見えなくなる（忘れられる）。モデルによって数万〜数百万トークンとウィンドウの大きさが異なる。

    具体例: 長い会話を続けていると、途中でAIが最初の方に伝えた内容を忘れてしまうことがあるのは、コンテキストウィンドウの制約が関係している。

    ファインチューニング（Fine-tuning）¶

    一言でいうと: 学習済みのAIモデルに追加の学習をさせ、特定の用途に特化させる手法。

    ゼロからモデルを作るのは膨大なコストがかかるため、すでに広く学習済みのモデル（基盤モデル）をベースに、特定分野のデータで追加学習させることで、専門性の高い応答ができるように調整する。

    具体例: 医療分野の文章だけを追加学習させることで、医療関連の質問への回答精度を高める、など。

    ハルシネーション（Hallucination）¶

    一言でいうと: AIが事実ではないことを、もっともらしく生成してしまう現象。

    LLMは「正しい情報を検索して答える」のではなく、「学習したパターンから、それらしい文章を予測して生成する」仕組みのため、存在しない情報や誤った情報を自信満々に答えてしまうことがある。特に固有名詞・数値・出典の引用などで起こりやすい。

    具体例: 実在しない書籍名や、誤った統計データを、あたかも事実のように回答してしまうケース。

    RAG（検索拡張生成、Retrieval-Augmented Generation）¶

    一言でいうと: AIが回答する前に、関連する情報を外部から検索して参照させる仕組み。

    LLM単体は学習時点の知識しか持たないが、RAGを使うと、質問に関連する文書をあらかじめ検索・取得し、その内容を踏まえて回答を生成できる。これにより、最新情報や、AIが学習していない社内資料などにも対応できるようになる。NotebookLMのような「資料に基づいて回答するAI」もこの仕組みに近い。

    具体例: 社内マニュアルを検索対象にして、そこに書かれている内容をもとに質問に答えるチャットボット。

    推論（Reasoning）¶

    一言でいうと: AIが答えを出す前に、段階的に考えるプロセス。

    近年のAIモデルには、いきなり答えを出すのではなく、途中の思考過程（考え方の手順）を組み立ててから最終的な回答を導く「推論モデル」がある。複雑な計算や論理的な問題に強くなる一方、応答に時間がかかる傾向がある。

    具体例: 数学の文章題を解く際に、途中式を組み立てながら順を追って答えを導き出す動作。

    パラメータ（Parameter）¶

    一言でいうと: AIモデルの内部にある、学習によって調整される数値。

    LLMは大量のパラメータ（数十億〜数兆個）の組み合わせによって、入力に対する出力を決めている。一般的に、パラメータ数が多いほど表現力は高くなるが、その分、計算コストも大きくなる。モデルの「大きさ」を表す指標としてよく使われる。

    具体例: 「70億パラメータのモデル」のように、モデルの規模を表す単位として使われる。

    学習データ / 事前学習（Training Data / Pre-training）¶

    一言でいうと: AIモデルを訓練するために使われる大量のテキストデータと、その学習プロセス。

    LLMは、インターネット上の文章や書籍など膨大なテキストデータを使って「事前学習」される。この段階で言語のパターンや知識を身につける。学習データの質や範囲が、モデルの得意・不得意分野に影響する。

    具体例: 学習データに含まれていない、非常に新しい出来事についてはAIが正しく答えられないことが多い。

    マルチモーダル（Multimodal）¶

    一言でいうと: テキストだけでなく、画像・音声・動画など複数の種類の情報を扱える能力。

    従来のAIはテキストのみを扱うものが多かったが、近年のモデルは画像を読み込んで説明したり、音声を理解したりできるようになっている。「モード（modal）」とはデータの種類（様式）のことで、それを複数（マルチ）扱えるという意味。

    具体例: 写真をアップロードして「この画像に写っているものを説明して」と頼む使い方。

    エージェント（AIエージェント）¶

    一言でいうと: 与えられた目標に対して、AIが自律的に計画を立て、ツールを使いながらタスクを遂行する仕組み。

    通常のチャットAIが「質問に答える」だけなのに対し、エージェントは「ファイルを読む」「コードを実行する」「Web検索する」といった外部ツールを自分で判断して呼び出しながら、複数の手順が必要なタスクを最後まで進める。Claude Codeなどのコーディングツールはエージェントの代表例。

    具体例: 「このバグを直して」という指示に対し、AIが自分でコードを読み、原因を特定し、修正し、動作確認まで行う。

    システムプロンプト（System Prompt）¶

    一言でいうと: AIの振る舞い方をあらかじめ設定しておく、会話の裏側にある指示文。

    ユーザーが直接入力するプロンプトとは別に、「あなたは〇〇として振る舞ってください」といった役割や制約をあらかじめ設定できる。多くのツールの「カスタム指示」機能はこのシステムプロンプトを設定する仕組み。

    具体例: 「常に日本語で、簡潔に回答してください」という指示をあらかじめ設定しておく。

    温度（Temperature）パラメータ¶

    一言でいうと: AIの応答の「ランダムさ・多様性」を調整する数値。

    温度を低くすると、AIは最も可能性の高い（無難な）応答を選びやすくなり、一貫性のある堅実な出力になる。温度を高くすると、多様で創造的だが、時に予測しづらい応答になりやすい。多くのチャットツールでは裏側で固定値が使われており、ユーザーが直接触ることは少ないが、API利用時には調整可能なことが多い。

    具体例: 創造的な文章（小説のアイデア出し等）には高めの温度、正確性が求められる回答には低めの温度が向いている。

    2. プログラミング関連用語（利用者向けレベル）¶

    API（Application Programming Interface）¶

    一言でいうと: 異なるソフトウェア同士がやり取りするための「窓口」のような仕組み。

    自分でAIモデルを作らなくても、APIを通じて命令を送ると、AI側が処理した結果を返してくれる。ChatGPTやClaudeを自分のアプリやサービスに組み込む際は、多くの場合このAPIを利用する。

    具体例: 自作のアプリから「この文章を要約して」というリクエストをClaude APIに送り、要約結果を受け取る。

    リポジトリ（Repository）¶

    一言でいうと: プログラムのソースコードやファイルを保管しておく場所。

    「Repo（リポ）」と略されることも多い。GitHubなどのサービス上で管理されることが多く、変更履歴を記録しながらファイル群を一元管理できる。AIコーディングツールに「このリポジトリを直して」と頼む、という使い方をする。

    具体例: あるアプリのソースコード一式が入ったフォルダ（＋変更履歴）が1つのリポジトリになっている。

    コマンドライン（CLI, Command Line Interface）¶

    一言でいうと: マウス操作ではなく、文字によるコマンド（命令文）でコンピュータを操作する画面。

    「ターミナル」とも呼ばれる。アイコンをクリックする代わりに、キーボードで命令を入力して実行する。Claude CodeやCodexなど、AIコーディングツールの多くはこのCLI上で動作する。

    具体例: mkdocs serve と入力してEnterキーを押すと、ローカルサーバーが起動する。

    変数（Variable）¶

    一言でいうと: プログラムの中で、値を一時的に入れておく「箱」のようなもの。

    名前をつけた箱に数値や文字列を入れておき、後からその名前で値を呼び出したり書き換えたりできる。AIに生成してもらったコードを読む際、最初につまずきやすい概念のひとつ。

    具体例: name = "大輝" と書くと、nameという変数に「大輝」という文字列が入る。

    リクエスト / レスポンス（Request / Response）¶

    一言でいうと: 「依頼する側からの要求」と「それに対する返答」という、通信の基本的なやり取りの単位。

    アプリやブラウザがサーバー（AIも含む）に対して「これを処理して」と送るのがリクエスト、それに対してサーバー側が返す結果がレスポンス。API利用時に頻出する用語。

    具体例: ブラウザでWebページを開く動作も、裏側では「ページをください」というリクエストと、それに応える「ページのデータ」というレスポンスのやり取りが行われている。

    環境構築（Environment Setup）¶

    一言でいうと: プログラムやツールを動かすために、必要なソフトウェアや設定を整える作業。

    あるツールを使うには、対応するプログラミング言語や関連ソフトのインストール、設定ファイルの用意などが必要になることが多い。この一連の準備作業をまとめて「環境構築」と呼ぶ。

    具体例: このサイトの構築でも、Pythonの仮想環境を作り、MkDocsをインストールする、という環境構築を行っている。

    バージョン管理（Git）¶

    一言でいうと: ファイルの変更履歴を記録し、いつでも過去の状態に戻したり、変更内容を比較したりできる仕組み。

    「Git」はバージョン管理を行うための代表的なツール。誰が・いつ・どこを変更したかを記録できるため、複数人での共同作業や、AIによる自動編集の内容を確認する際にも役立つ。GitHubはこのGitをクラウド上で使えるようにしたサービス。

    具体例: AIにコードを編集してもらった後、Gitの差分（diff）を見て「どこが変更されたか」を確認する。

    ライブラリ / パッケージ（Library / Package）¶

    一言でいうと: よく使う機能をあらかじめまとめておき、誰でも簡単に呼び出して使えるようにしたプログラムの部品集。

    ゼロから全てのプログラムを書く代わりに、他の人が作った便利な機能（ライブラリ）を組み込んで使うのが一般的。「パッケージ」もほぼ同じ意味で使われる。このサイトの構築で使っている「mkdocs-material」もパッケージの一つ。

    具体例: グラフを描画する機能をまとめたライブラリを読み込むことで、自分でグラフの描画処理を1から書かなくて済む。

    3. ファイル・サイトの仕組みに関する用語¶

    出力形式（テキスト / Markdown / HTML 等）¶

    一言でいうと: AIが生成する文章や、Webページが作られる際の「書き方のルール」。

    同じ内容でも、書き方のルール（形式）によって見た目や用途が変わる。プレーンテキストは装飾のない普通の文章、Markdownは見出しや箇条書きなどを簡単な記号で表現できる書き方、HTMLはブラウザが解釈してレイアウトを表示するための言語。このサイト自体もMarkdownで書かれた文章を、MkDocsがHTMLに変換して表示している。

    具体例: 「# 見出し」とMarkdownで書くと、Webページ上では大きな見出し文字として表示される。

    ファイル形式（.md, .pdf, .csv 等）¶

    一言でいうと: ファイルの中身がどのような種類のデータかを表す分類。拡張子（ファイル名の末尾の文字列）で区別される。

    .mdはMarkdown文書、.pdfは印刷レイアウトを保ったまま閲覧できる文書、.csvは表形式のデータをカンマ区切りで保存したものなど、それぞれ用途が異なる。AIツールに資料を読み込ませる際は、対応しているファイル形式を確認する必要がある。

    具体例: NotebookLMはPDFやGoogleドキュメントなど複数のファイル形式を情報源として読み込める。

    トークン制限とファイルサイズの関係¶

    一言でいうと: AIに読み込ませられる文章量には上限があり、それはファイルの「容量（MB）」ではなく「トークン数」で決まる。

    同じファイルサイズ（MB）でも、画像が多いPDFと文字だけのテキストファイルでは、AIが処理する際のトークン数は大きく異なる。長い資料をAIに読み込ませる際にエラーになる場合、ファイル容量ではなく、コンテキストウィンドウのトークン上限を超えていることが原因であることが多い。

    具体例: 数百ページにわたる資料をそのまま読み込ませようとすると、ファイルサイズ自体は小さくても、トークン数の上限を超えてエラーになることがある。

    静的サイト / 動的サイト（Static Site / Dynamic Site）¶

    一言でいうと: あらかじめ完成した状態のページを表示する「静的サイト」と、アクセスのたびにサーバー側で内容を組み立てて表示する「動的サイト」。

    静的サイトは、事前に生成されたHTMLファイルをそのまま表示するだけなので表示が速く、構成もシンプル。このサイト（MkDocsで構築）も静的サイトの一種。一方、動的サイトはユーザーごとに異なる内容を表示したり、データベースと連動したりできるが、その分仕組みが複雑になる。

    具体例: ログイン状態によって表示内容が変わるサイトは、動的サイトに分類されることが多い。

    ホスティング（Hosting）¶

    一言でいうと: 作成したWebサイトのデータをインターネット上に置き、誰でもアクセスできるようにするサービス。

    サイトを作っただけでは自分のパソコンの中にあるだけで、他の人はアクセスできない。ホスティングサービス（GitHub Pages、Vercelなど）にサイトのデータを配置することで、URLを通じて誰でも閲覧できるようになる。

    具体例: このサイトも現状はローカル環境（自分のパソコン内）でのみ閲覧できる状態だが、将来的にGitHub Pages等でホスティングすることで、外部からアクセス可能にできる。
