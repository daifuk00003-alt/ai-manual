    セキュリティ・リテラシー¶

    AIツールは便利だが、「何を」「どこまで」入力していいかを考えずに使うと、情報漏えいや法令違反につながることがある。このページでは、AIに情報を入力するときの基本的な考え方から、個人情報・機密情報を扱う際の具体的な判断方法までをまとめる。

    このページの位置づけ

    ここに書いているのは一般的な考え方の整理であり、法律の専門的な助言（法律相談）ではない。学校・会社などの組織に所属している場合は、まず自組織の情報セキュリティポリシーや個人情報保護の担当部署に確認するのが最優先。各AIツールのデータの取り扱い方針は改定されることがあるため、重要な判断の前には必ずツール側の最新の利用規約・プライバシーポリシーを確認すること。

    1. まず押さえておきたい基本の考え方¶

    「入力する」は「外部に送信する」と同じ¶

    チャットAIに文字を打ち込むという行為は、手元のメモ帳に書くのとは違い、その内容がインターネット経由で外部の会社のサーバーに送信される。会話が便利に「記憶」されているように見えても、実体はサーバー側に保存されたデータであり、自分のPCの中だけで完結しているわけではない。

    「学習に使われる」と「レビューされる」は別の話¶

    AIに入力した内容の扱われ方には、大きく分けて2つの論点がある。

    • モデルの学習データに使われるか — 入力した内容が、AIの性能を改善するための学習素材として使われる可能性があるかどうか。学習に使われた場合、理屈上はその情報の断片が将来の別の回答に何らかの形で影響する可能性がゼロではない。
    • 人間のレビュアーに見られる可能性があるか — 学習に使う・使わないとは別に、不正利用の監視や品質改善のために、担当者が会話内容を閲覧する場合がある（多くの場合、匿名化された一部サンプルが対象だが、規約上は「見られる可能性がある」こと自体を認識しておく必要がある）。

    一般的な傾向として、個人向けの無料プラン・一般プランは学習やレビューに使われる可能性が高く、法人向け・組織向けプラン（Team/Enterprise/API経由など）は契約上「学習に使わない」ことが明記されていることが多い。ただしこれは各社の方針変更で変わりうるため、「無料だから危ない／有料だから安全」と単純に決めつけず、都度設定画面を確認する習慣が重要。

    削除しても消えたとは限らない¶

    チャットの履歴を削除しても、法令対応（不正利用の調査など）のために一定期間サーバー側にデータが保持される場合がある。「消したから大丈夫」ではなく、そもそも入力しないことが最も確実な対策になる。

    判断に迷ったときの原則

    「この内容を、相手の会社の問い合わせ窓口やコールセンターのオペレーターに口頭で伝えられるか？」を基準にすると考えやすい。伝えられないと感じる内容（本人の同意を得ていない個人の詳しい情報、社外秘の資料など）は、AIにもそのままの形では入力しない。

    2. 個人情報は入れていいのか？ ― 具体例で考える¶

    そもそも「個人情報」とは¶

    氏名・生年月日・住所のように特定の個人を識別できる情報全般を指す。日本の個人情報保護法では、その中でも人種・信条・病歴・犯罪歴・成績や指導記録などの評価情報、健康診断の結果といった特に取り扱いに注意が必要なものを「要配慮個人情報」として、より厳格な取り扱い（原則、本人の同意なしの第三者提供・目的外利用の禁止）を求めている。学校が扱う成績・出欠・健康・家庭環境の情報は、この要配慮個人情報に該当しうるものが多い。

    ケース: 先生が生徒の情報をAIに入れて相談したい¶

    「クラス全体の成績の傾向を分析してほしい」「この生徒への指導方法をAIに相談したい」という場面は非常に多いニーズだが、そのまま生の情報（氏名＋成績＋家庭状況など）を一般向けのAIサービスに入力するのは避けるべき。理由は次の通り。

    • 生徒本人・保護者の同意なく、外部の民間サービスに個人情報を提供することになり、学校の個人情報保護方針や教育委員会の情報セキュリティポリシーに抵触する可能性が高い。
    • 入力した情報が意図せず学習・保存され、将来的に流出・再利用されるリスクをゼロにできない。
    • 仮に匿名化したつもりでも、「学年・クラス・特徴的なエピソード」の組み合わせだけで本人が特定できてしまう（再識別リスク）ことがある。

    代替案¶

    代替案 具体的なやり方 向いている場面
    匿名化・仮名化してから入力する 氏名を「生徒A」「生徒B」に置き換える。学年・クラス・性別など特定につながる属性も削る。複数人の傾向をまとめて聞き、個票を出さない（例：「クラス30人のうち、こういう間違い方をする生徒が多い場合、どう教え方を変えるとよいか」） 日常的な指導方法の相談、教材の作り方の相談など、個人を特定する必要がない相談全般
    学校・自治体が契約している法人向けAIサービスを使う 教育委員会や学校法人が契約する、データを学習に使わない契約（DPA：データ処理契約）付きのEnterprise版・教育機関向けプランを利用する 個票（実名や詳細な成績データ）を扱う必要がある業務
    ローカルで完結するAIを使う Ollamaなど、インターネットに送信せずPC内で動くAIモデルを使う（Obsidianのようなローカル保管庫との組み合わせも含む） 学校のIT環境で許可されており、かつ技術的なセットアップができる場合
    統計的な傾向だけを聞く 個人が特定できるデータを渡さず、「一般的にこういう傾向の生徒にはどう対応するとよいか」という一般論として相談する AIに「答え」を求めるのではなく「考え方の壁打ち相手」として使いたい場合

    迷ったら学校・教育委員会のルールが最優先

    法律だけでなく、多くの学校・自治体では独自の「ICT利用ガイドライン」「生成AI利用ガイドライン」を定めている。個人的な判断でAIに生徒情報を入力する前に、まず職場のルールを確認すること。文部科学省も学校向けの生成AIガイドラインを公表しており、参考になる。

    判断のミニチェックリスト¶

    AIに何かを入力する前に、次を自問する。

    1. その情報から、本人（自分以外の誰か）が特定できるか？
    2. 本人・保護者の同意を得ているか？
    3. 入力先は「学習に使わない」契約になっているか（法人向けプランか）？
    4. 匿名化・仮名化できないか？
    5. そもそもAIに聞かなくても、自分で判断できる範囲ではないか？

    1つでも「できない／わからない」があれば、入力を止めて代替案を検討する。

    3. マル秘情報（会社の機密情報など）の管理¶

    何が「マル秘」に当たるか¶

    学校の生徒情報に限らず、仕事で扱う次のような情報も、外部のAIサービスに安易に入力してはいけない「マル秘情報」にあたる。

    • 未公開の決算情報・経営計画・M&Aなどのインサイダー情報
    • 顧客リスト・取引先の非公開の契約条件
    • 社外秘の企画書・設計図・ソースコード（NDA＝秘密保持契約の対象になっているもの）
    • 社員の人事評価・給与・健康情報などの人事情報
    • パスワード・APIキー・社内システムの認証情報

    入力前チェックリスト¶

    • [ ] この情報が外部に漏れたら、会社・取引先・自分自身に実害が出るか？
    • [ ] NDA（秘密保持契約）の対象になっている情報ではないか？
    • [ ] 会社として「利用してよい」と正式に許可されたAIサービス・プランか？
    • [ ] 入力するAIサービスは、学習に使わない契約（法人向けプラン／API経由）になっているか？
    • [ ] マスキング（固有名詞・数値・識別子を伏せ字にする）で代替できないか？

    安全な使い方のパターン¶

    • 会社が契約した法人向けプランを使う — 個人のアカウントではなく、会社が正式に契約したTeam/Enterprise版や、API経由で社内システムに組み込まれたAI（Claude（Cowork）や社内向けチャットボットなど）を使う。契約上、入力内容がモデルの学習に使われないことが明記されているのが一般的。
    • 抽象化してから聞く — 「A社との契約金額は◯◯円」ではなく、「業界水準と比べて契約金額の交渉余地はどれくらいありそうか」のように、固有名詞や具体的な数値を外した形で相談する。
    • 社内の文書管理ルールに従う — 資料をObsidianのような保管庫にまとめる場合も、社外に同期・共有される設定になっていないか確認する。

    絶対に入力してはいけないもの

    パスワード・APIキー・クレジットカード番号・マイナンバーなどの認証情報や機微情報は、どのAIサービスに対しても、どんな理由があっても入力しない。これらは「学習に使われるかどうか」以前に、その場でサービス提供者側の担当者に見える形でサーバーに送信されてしまう情報であり、代替案も存在しない（安全に扱う方法自体がない）と考えるべき。

    4. ツール別・データの取り扱いの傾向（早見表）¶

    各社の方針は変更されることがあるため、あくまで「確認すべきポイントの目安」として見る。実際に使う前には、必ずツール本体の設定画面（データ管理・プライバシー設定）を確認すること。

    ツール 個人向けプランの一般的な傾向 確認すべき設定 法人向けプランの傾向
    ChatGPT 既定では会話が改善目的で使われうる 設定 → データ管理 の「モデル改善のためのデータ共有」トグル Team/Enterprise/API経由は既定で学習に不使用
    Claude（チャット） プラン・時期によって既定挙動が変わることがある 設定内のプライバシー・データ管理項目を都度確認 Team/Enterprise（Claude for Work）は契約上学習に不使用
    Gemini 既定で「アクティビティ」が有効だと人によるレビュー対象になりうる 「Gemini Appsのアクティビティ」設定 Google Workspace版は学習に不使用・データ保護契約あり
    NotebookLM アップロードした資料をモデル学習に使わない方針を明示 最新のプライバシーに関する説明ページ 教育機関・法人向け提供あり
    Obsidian ローカル保存が基本、AI機能を使わない限り外部送信されない 使用しているプラグインが外部AI連携をしていないか クラウド同期機能を使う場合は同期先の設定を確認

    5. まとめ：入力前の最終チェック¶

    入力しようとしている内容に、個人情報・機密情報が含まれるか？
├─ 含まれない → 通常通り入力してOK
└─ 含まれる
    ├─ 匿名化・抽象化できる → 匿名化・抽象化してから入力
    └─ できない
        ├─ 学習しない契約の法人向けプランがある → それを使う
        └─ ない → 入力しない（自分で判断する／担当部署に相談する）
