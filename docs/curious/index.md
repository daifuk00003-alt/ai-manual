#### Git・GitHub・リポジトリ・プッシュ・デプロイ・Vercelの違い

似た言葉が多くて混乱しやすいところ。実はちょうど今回、このサイトを公開する作業の中で全部使ったので、それを例に整理する。

**一言でいうと**: それぞれ「役割」が違う。Gitは変更履歴を記録する仕組み、リポジトリはその履歴とファイルが入った箱、GitHubはその箱をインターネット上に置くサービス、プッシュは手元の変更をその箱に送る操作、デプロイはファイルを実際にアクセスできる状態にする作業、Vercelはデプロイをしてくれる別の会社のサービス。

もう少し詳しく、1つずつ:

- **Git**: ファイルの変更履歴を記録する仕組み(技術そのもの)。Wordの「変更履歴」機能に近いが、複数のファイルをまとめて管理できる。誰が・いつ・何を変えたかを記録し、過去のバージョンに戻すこともできる。自分のパソコンの中だけでも使えるもので、インターネットは関係ない。今回、`ai-manual`フォルダで`git init`というコマンドを実行した瞬間から、このフォルダの変更履歴がGitで記録され始めた。
- **リポジトリ(Repository)**: Gitで管理されているファイル一式+変更履歴が入った「箱」のこと。`ai-manual`フォルダそのものが、`git init`した時点でリポジトリになった。
- **GitHub**: リポジトリをインターネット上に保管して、どこからでもアクセスしたり、他の人と共有したりできるようにする「サービス」。自分のパソコンの中にしかなかったリポジトリのコピーをGitHub上にも置くことで、パソコンが壊れてもデータが残ったり、他の場所からも同じプロジェクトを見られるようになる。今回は`daifuk00003-alt/ai-manual`というリポジトリをGitHub上に作った。
- **プッシュ(push)**: 「手元のパソコンにあるリポジトリの最新の変更を、GitHub上のリポジトリに送って反映させる」操作。手元で書いた原稿を、クラウドの倉庫に「これが最新版です」と送るイメージ。今回、ファイルを編集するたびに`git push`していた。
- **デプロイ(deploy)**: 書いたファイルを、実際に誰かがブラウザで見られる状態にする作業。GitHubにプッシュしただけでは、まだ「ソースコード(元になるファイル)が保管されている」だけで、Webサイトとして表示される状態にはなっていない。今回は`mkdocs gh-deploy`というコマンドで、Markdownファイルを実際に表示できるHTMLというファイル形式に変換し、それを「GitHub Pages」という表示専用の置き場所に送った。これで初めて `https://daifuk00003-alt.github.io/ai-manual/` というURLで実際にアクセスできるようになった。この一連の作業が「デプロイ」。
- **Vercel**: GitHub Pagesと似た役割を持つ、別の会社が提供するデプロイ・ホスティング(サイトを置いておく)サービス。GitHubのリポジトリと連携させておくと、プッシュするたびに自動でデプロイしてくれる点はGitHub Pagesと共通している。今回のような単純なMarkdownサイトはGitHub Pagesで十分だが、もっと複雑な(裏側でデータ処理が必要な)Webアプリを作る場合は、Vercelのようなサービスが使われることが多い。

**具体例**: 今回の一連の流れをまとめると、「`ai-manual`フォルダをリポジトリ化(Git)→GitHub上に置き場所を作成(GitHub)→手元の変更をそこに送信(プッシュ)→実際に見られる形にして公開(デプロイ、今回はGitHub Pages)」という順番になる。

#### フロントエンドとバックエンドの違い

**一言でいうと**: フロントエンドは「ユーザーが直接目にする画面側」、バックエンドは「画面には出てこない、裏側でデータ処理をする部分」。

もう少し詳しく:

- **フロントエンド**: ブラウザの中で動く部分。画面のレイアウト、文字や画像の見た目、ボタンを押した時の動き等を担当する。主にHTML・CSS・JavaScriptという言語で作られ、ユーザーのパソコンやスマホの中で実行される。
- **バックエンド**: ユーザーからは直接見えない、サーバー(どこか別のコンピューター)側で動く部分。データベースとのやり取り、ログイン処理、複雑な計算等を担当する。Python・Node.js・Goなど様々な言語が使われる。

**具体例**: ネット通販サイトで例えると、「商品一覧の見た目」「カートに追加ボタン」はフロントエンド。「実際に在庫があるか確認する」「注文情報をデータベースに保存する」処理はバックエンド。

このai-manualサイト自体で言うと: MkDocsで作った今のサイトは、事前にすべてHTMLファイルへ変換されて置いてあるだけの「[静的サイト](../glossary/index.md#static-site-dynamic-site)」なので、実質的にフロントエンドしか存在しない(バックエンドがない)。データ処理をする裏側の仕組みが不要なぶん、GitHub Pagesのようなシンプルな置き場所だけで公開できている。
