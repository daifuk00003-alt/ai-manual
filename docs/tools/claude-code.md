# Claude（Code）

ターミナル上（CLI）で動作するAIコーディングエージェント「Claude Code」。実際にこのAI活用マニュアルのサイト自体も、Claude Codeを使って構築されている。

## 1. 概要

- **何ができるツールか**: コードの読み書き・編集、ファイル検索、コマンドの実行（ビルド・テスト・Git操作等）、複数ファイルにまたがる修正、バグ調査から実装・動作確認までを一貫して行える。単発の応答を返すだけでなく、必要な作業を自分で計画し、複数の手順を踏んで最後までやり遂げる「[エージェント](../glossary/index.md#ai)」として動作する点が最大の特徴。
- **提供形態**: ターミナルで動く[CLI](../glossary/index.md#cli-command-line-interface)が基本形態。加えてデスクトップアプリやIDE拡張（VS Code等）からも利用できる。
- **通常のチャットモードとの違い**: [Claude（チャット）](claude-chat.md)は「対話して情報を受け取る」ツールだが、Claude Codeは実際に自分の環境（[リポジトリ](../glossary/index.md#repository)内のファイルやターミナル）に対して読み書き・実行を行える点が根本的に異なる。

## 2. 仕組み

- **エージェント型AIの基本的な考え方**: 「このバグを直して」といった目標を渡すと、Claude Codeは自分でファイルを検索して原因箇所を特定し、修正を加え、必要であればテストやビルドを実行して結果を確認する、という一連の流れを自律的に進める。用語集の[エージェント](../glossary/index.md#ai)の項目で説明した仕組みそのもの。
- **利用可能な「ツール」**: ファイルの読み書き、テキスト検索、ターミナルコマンド（Bash）の実行、Web検索など、あらかじめ用意された「ツール」を状況に応じて自分で選んで呼び出しながら作業を進める。
- **権限モード**: ファイルの変更やコマンドの実行の前に、都度ユーザーの確認を求めるモードと、あらかじめ許可した範囲内であれば確認なしに進めるモードなど、安全性と効率のバランスを選べるようになっている。特に、変更を取り消しにくい操作（強制的な上書き・削除等）については、慎重に確認を挟むのが基本的な考え方。
- **サブエージェント・スキルなどの拡張**: 特定の作業（コードレビュー、探索調査等）に特化した「サブエージェント」を呼び出したり、繰り返し行う定型作業を「スキル」として登録し呼び出したりすることで、複雑なタスクを整理しながら進められる。

## 3. 基本的な使い方

1. **インストール〜起動**: ターミナルにインストールし、作業したいプロジェクトのフォルダで起動する。
2. **やりたいことを指示する**: 「〇〇の機能を追加して」「このエラーの原因を調べて直して」のように、目的を自然な言葉で伝える。
3. **権限を確認・承認する**: ファイルの変更やコマンドの実行について、内容を確認しながら進める。意図と違う変更が行われていないか、都度チェックするのが望ましい。

## 4. 具体例

- 「ログイン画面でエラーが出る不具合を直して」と伝え、原因調査から修正、動作確認までを任せる。
- 「この関数にテストを追加して」と依頼し、既存コードの書き方に沿ったテストコードを生成してもらう。
- 「このコードをレビューして、改善点を教えて」と依頼し、可読性や設計面の指摘を受ける。
- このサイトのように、「要件定義書をもとにMkDocsサイトを作って」といった、環境構築からファイル作成までを含む一連の作業を任せる。

## 5. 注意点・限界

- **意図しない変更・削除のリスク**: 自律的にファイルを操作できる分、意図しない変更や削除が行われるリスクもゼロではない。特に取り消しにくい操作（Gitの強制的な上書き、ファイルの完全削除等）は、慎重に確認する必要がある。
- **実行結果の確認の重要性**: 「動いているように見える」ことと「正しく動いている」ことは別。生成・修正されたコードは、実際に動かして確認することが欠かせない。
- **料金・利用量の考え方**: チャット利用と同様に、やり取りする文章量（[トークン](../glossary/index.md#token)数）に応じて利用量がカウントされる。大きなリポジトリを何度も読み込ませるような作業は、その分利用量も増えやすい。

## 6. 他ツールとの比較

| 観点 | Claude（Code） | Codex |
|---|---|---|
| 強み | 長い[コンテキストウィンドウ](../glossary/index.md#context-window)を活かした大規模なリポジトリの読解・横断的な修正、サブエージェントやスキルによる作業の整理のしやすさ | OpenAIのエコシステム（ChatGPT等）との親和性、クラウド実行によるバックグラウンドでのタスク処理のしやすさ、サンドボックス実行を前提とした安全な自動実行 |
| 弱み | 画像生成等コーディング以外の周辺タスクは他ツールとの併用が必要 | エコシステムやツール構成が変化中で、情報が流動的な部分がある |
