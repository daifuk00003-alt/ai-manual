# Obsidian等の保管庫（ボールト）系ツールとの連携方法

Markdownベースのノート管理ツール「Obsidian」を中心に、AIツールとの連携方法を扱う。ここまでのツールが「AIそのもの」だったのに対し、Obsidianは「自分の知識やログを蓄積する場所」であり、AIと組み合わせることで真価を発揮しやすい。

## 1. 概要

- **Obsidianとは何か**: パソコン上のローカルフォルダに、ノートを[Markdown](../glossary/index.md#markdown-html)形式のファイルとして保存していくノートアプリ。クラウドサービスに依存せず、自分のファイルとしてデータを持てる点が特徴。
- **「保管庫（Vault）」という考え方**: Obsidianでは、ノートをまとめるフォルダ全体を「保管庫（Vault）」と呼ぶ。1つの保管庫の中で、ノート同士をリンクさせながら、知識やログを蓄積していく。
- **AIツールとの連携が求められる背景**: 保管庫の中身は普通のMarkdownファイルの集まりなので、AI（特にファイルを読み書きできる[Claude（Code）](claude-code.md)のようなエージェント）と非常に相性がよく、日記の整理・情報の要約・自動的なノート作成など、蓄積と自動化を組み合わせた活用がしやすい。

## 2. 仕組み

- **ファイルベースで持つ仕組み**: データベースやクラウド上の独自形式ではなく、ただのテキストファイル（[Markdown](../glossary/index.md#markdown-html)）としてすべてのノートが保存される。これにより、Obsidian以外のアプリやAIツールからも、直接ファイルを読み書きできる。
- **プラグインによる拡張**: 標準機能に加えて、コミュニティが作成した多数のプラグインを追加することで、カレンダー表示、グラフビュー、外部サービス連携など、さまざまな機能を拡張できる。
- **AI連携の方式**: 大きく分けて、(1) AIとの対話内容を手動でコピー&ペーストしてノートに保存する方法、(2) Obsidianのプラグイン経由でAI（API）と連携する方法、(3) Claude Codeのような外部のエージェントに保管庫のフォルダを直接読み書きさせる方法がある。(3)の方法は、保管庫がただのファイル群であることを活かした連携で、日記の自動整理やログの蓄積・要約といった自動化と特に相性がよい。

## 3. 基本的な使い方

1. **保管庫を作成する**: パソコン上の任意のフォルダを指定して、新しい保管庫を作成する。
2. **ノートを作成・リンクする**: Markdown形式でノートを書き、`[[ノート名]]`のような記法で、ノート同士をリンクさせながら知識を積み上げていく。
3. **AIと連携する**: 例えばClaude Codeから保管庫のフォルダを指定し、「今日の日記のフォーマットに沿って、この内容を整理して追記して」のように依頼すると、保管庫内のMarkdownファイルを直接読み書きしてもらえる。

## 4. 具体例

- 日々の日記やメモをAIに整理させ、決まったフォーマットのノートとして保管庫に追記する。
- 会議の議事録やAIとの壁打ちの内容を、後から見返しやすい形にまとめてノート化する。
- 蓄積したノートをAIに読ませて、「今月書いたことの傾向をまとめて」のように振り返りに使う。

## 5. 注意点・限界

- **同期・バックアップ**: ローカルファイルとして保存される分、複数端末での同期や、誤って削除した際のバックアップは自分で用意する必要がある（同期用のプラグインやクラウドストレージとの併用が一般的）。
- **データ取り扱いの注意点**: AIツールにローカルファイルを渡す・読み書きさせる場合、個人的な内容や機密情報が含まれるノートをどこまでAIに見せてよいかを意識しておく必要がある。

## 6. 他ツールとの比較

| 観点 | Obsidian | その他のクラウド型ノートツール |
|---|---|---|
| 強み | データをローカルのMarkdownファイルとして保持でき、AIエージェントによる直接的なファイル読み書きと相性がよい。プラグインによる高い拡張性 | 複数端末での同期や共同編集が標準で使いやすい |
| 弱み | 同期・バックアップを自分で設定する必要がある | データが独自形式やクラウド側に閉じていることが多く、外部のAIエージェントから直接ファイルを読み書きする連携がしにくい場合がある |
