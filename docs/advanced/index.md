# 応用編

「ツール別基礎編」で学んだ各ツールの基礎を踏まえ、複数のツールを組み合わせた発展的な活用法をまとめます。

「基礎編」が個々のツールの使い方だったのに対し、こちらは複数ツールをまたぐワークフローや、より発展的な仕組みの解説が中心になります。まだ各ツールの基礎に自信がない場合は、先に[ツール別基礎編](../tools/index.md)に目を通しておくと理解しやすくなります。

## 1. 複数ツールを組み合わせたワークフロー例

単体のツールで完結させるより、それぞれの得意分野をリレーのようにつなぐと、質・速さの両面で良い結果になりやすい。

### ワークフローA: 資料調査 → 壁打ち → 実装

「資料を理解する」「考えを整理する」「形にする」を、それぞれ得意なツールに任せる流れ。

1. **[NotebookLM](../tools/notebooklm.md)で資料整理** — 関連資料（仕様書・議事録・参考記事など）をまとめて読み込ませ、要点や矛盾点を洗い出す。資料の範囲に回答が限定されるため、事実確認の土台として使いやすい。
2. **[Claude（チャット）](../tools/claude-chat.md)で壁打ち** — NotebookLMで整理した要点をもとに、方針や構成をClaudeと対話しながら詰める。Projectsに資料をまとめておくと、会話をまたいでも前提がぶれにくい。
3. **[Claude（Code）](../tools/claude-code.md)で実装** — 固まった方針をもとに、実際のコードやサイトの構築をエージェントに任せる。このAI活用マニュアル自体も、まさにこの3ステップに近い流れで作られている。

### ワークフローB: 検索・調査 → 構成案作成 → 蓄積

「最新情報を集める」「文章にまとめる」「後から使える形で残す」を分担する流れ。

1. **[Gemini](../tools/gemini.md)で検索・調査** — Google検索と連携した強みを活かし、最新の情報を集める。
2. **[ChatGPT](../tools/chatgpt.md)で構成案作成** — 集めた情報をもとに、文章の構成案や下書きを作る。
3. **[Obsidian](../tools/obsidian.md)に蓄積** — 出来上がった内容を、後から検索・再利用できる形でノートとして保管庫に残す。

### ワークフローC: 日々のログ蓄積 → 自動整理

継続的な記録と、その定期的な整理を分担する流れ。

1. **書く**: 日々の出来事や気づきを、決まったフォーマットでObsidianの保管庫にメモしていく。
2. **整理を任せる**: [Claude（Code）](../tools/claude-code.md)のようなファイルを直接読み書きできるエージェントに保管庫を指定し、「今週分のメモを要約して」「共通するテーマを見つけて」のように整理・要約を依頼する。
3. **溜まったログを資産にする**: 整理された内容が保管庫に蓄積されていくことで、後から自分の考えの変化や傾向を振り返れる資産になる。

## 2. 発展的な仕組みの解説

### MCP（Model Context Protocol）

AIと外部ツール（Slack、Gmail、ファイルシステムなど）をつなぐための、共通の「接続規格」。ツールごとにバラバラの連携方法を個別に用意する代わりに、MCPという共通の窓口に対応させることで、どのAIからでも同じ方法で外部ツールを呼び出せるようにする仕組み。[Claude（Cowork）](../tools/claude-cowork.md)がSlackやGmailと連携できるのは、このMCPの仕組みを通じてコネクタ（プラグイン）が用意されているため。

### サブエージェント／マルチエージェントの考え方

1つのAIがすべての作業を最初から最後まで担当するのではなく、役割ごとに分けた複数のAI（サブエージェント）に作業を分担させる考え方。たとえば「調査担当」「実装担当」「レビュー担当」のように役割を分けることで、それぞれが集中すべき範囲が明確になり、複雑なタスクでも一貫性を保ちやすくなる。[Claude（Code）](../tools/claude-code.md)のサブエージェント機能は、この考え方を1つのツールの中で実現したもの。

### RAG（検索拡張生成）を自分の資料に応用する考え方

用語集で紹介した[RAG](../glossary/index.md#ragretrieval-augmented-generation)は、「AIに質問する前に、関連する自分の資料を検索して読ませる」という仕組みだった。これは特別な開発をしなくても、日常的な使い方の中で応用できる。

- [NotebookLM](../tools/notebooklm.md)に自分の資料を読み込ませて質問する使い方は、RAGをそのまま体験できる代表例。
- [Claude（チャット）](../tools/claude-chat.md)のProjectsに関連資料をまとめておくのも、同じ考え方の応用。
- [Obsidian](../tools/obsidian.md)の保管庫をAIエージェントに読ませる（ワークフローC）のも、「自分の蓄積した情報を検索対象にする」という意味で、広い意味でのRAG的な使い方といえる。

### プロンプト設計の発展

基本編で触れた[プロンプト](../glossary/index.md#prompt)の考え方を、もう一段発展させると次のような工夫がある。

- **役割設定**: 「あなたは経験豊富な編集者として」のように役割を与えると、その役割に沿った視点で応答してもらいやすくなる。
- **出力形式の指定**: 「表形式で」「300字以内で」「箇条書きで」のように、欲しい形をあらかじめ指定する。
- **Few-shot（具体例の提示）**: 期待する回答の見本を1〜2個示してから依頼すると、意図に近い形式・トーンで返ってきやすくなる。
- **段階を分けて依頼する**: 一度に全部を頼むのではなく、「まず構成案だけ出して」→「その構成で肉付けして」のように工程を分けると、途中で軌道修正しやすい。

## 3. 目的別の組み合わせガイド

| 目的 | おすすめの組み合わせ | ポイント |
|---|---|---|
| 調査・情報収集 | [Gemini](../tools/gemini.md) or [NotebookLM](../tools/notebooklm.md) → [Claude（チャット）](../tools/claude-chat.md) | 検索や資料に基づく事実収集はGemini/NotebookLMに任せ、そこからの解釈・整理はClaudeで行うと精度と柔軟性を両立しやすい |
| 文章作成・整理 | [ChatGPT](../tools/chatgpt.md) or [Claude（チャット）](../tools/claude-chat.md) → [Obsidian](../tools/obsidian.md) | 下書き・壁打ちをチャットAIで行い、完成したものをObsidianに蓄積して資産化する |
| 開発・実装 | [Claude（チャット）](../tools/claude-chat.md)で設計を固める → [Claude（Code）](../tools/claude-code.md) or [Codex](../tools/codex.md)で実装する | いきなり実装を任せるより、先に方針・設計をチャットで固めてからエージェントに実装させると手戻りが少ない |
